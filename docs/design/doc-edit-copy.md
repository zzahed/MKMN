# Edit a copy — design

Status: designed for the next release (Windows ARM64), on the Computer Use v3
foundation. This document is the contract for MKMN's document-aware editing
feature: the person picks ONE saved Word file, describes the edit in the
Computer Use composer, reviews what the model proposes, and gets an edited COPY
saved beside the source. The original is never modified, and formatting outside
the edited range is preserved byte for byte.

## Why a copy, and why not the window

The Word pass ended with a decision: writing INTO
Word's canvas needs a keyboard or coordinate path, and the action union has no
keyboard or coordinate kind on purpose — that is the Enter-safety guarantee of
Computer Use. This feature takes the OTHER road to the same goal. It does not
touch a window at all: it works on the saved `.docx` file itself, where the
document is just a zip of XML parts that this app can already read. No driver,
no grant, no window. The safety story is stronger than v1's: the feature cannot
send a keystroke anywhere because it never targets a process.

The loop is the same shape the person already knows from the agent strip:

**read → propose → validate → apply to the copy → reopen and verify → settle.**

## Pieces and ownership

- `src/core/docEdit.ts` — NEW, pure: bytes in, bytes out. The surgical engine
  (projection, matching, rewrite, verification). No fs, no model, no sidecar
  imports. Everything testable is here.
- `src/sidecar/docEditRun.ts` — NEW: the read → propose → validate → apply →
  verify loop. Dependency-injected exactly like `computerUse.ts` (an fs-shaped
  object `{ readFile, writeFile, rename, hash, exists, unlink }`, the model,
  `emit`, `signal`), so tests drive it with fakes and temp files.
- `src/sidecar/register/agent.ts` registers `agentDocEdit`; the run itself
  (`runDocEditAgent` in `src/sidecar/main.ts`) uses the SAME `agentRuns`
  AbortController map that backs `agentStopRun` and appShutdown, so Stop and
  shutdown work with no new code. It wraps its work in the
  `withChatSideLease` machinery exactly like `agentRun` does (same "chat" lease,
  same busy-then-refuse behavior).
- `src/shared/api.ts` + `src/renderer/tauriBridge.ts` — `docPickSource` (a
  native file dialog, Word filter docx/docm) and `docEditStart` (the sidecar
  call). The dialog lives in the bridge like `geniexPickLocal` and
  `foundryPickAudio` before it. No window grant is asked and none is given:
  `agentDocEdit` is deliberately NOT in the window-grant path.
- `src/renderer/computerUse.tsx` + `Chat.tsx` — the composer gains a document
  mode beside the window mode: pick a file, describe the edit, run. The run
  strip, Stop, and the settled verdict are reused unchanged; only the target row
  differs (the file's name, not a window title).
- `src/shared/stateMachines.json` — the `agentRun` machine description is
  broadened to cover document-edit runs (same states, same verdicts; "window"
  becomes "target"). Regenerated by the script as always.

## The editing path: a surgical string-level edit of `word/document.xml`

The obvious approach — parse the document part, mutate nodes, serialize — is
REJECTED: there is no XML serializer in this app (`xml.ts` parses, it does not
write), and building one only to re-emit a document risks shifting every byte
the person did not ask to change. The rebuild path in `office.ts`
(`buildDocx`) is doubly rejected: it rebuilds the WHOLE file from the markdown
text form and would lose formatting everywhere by construction.

The chosen path guarantees its central claim by construction: **the copy equals
the source except inside the edited ranges.** Concretely:

1. `readZip` the source into parts (the app's own zip reader/writer, in
   `zip.ts`).
2. `word/document.xml` is decoded and tokenized into **paragraphs**: each
   `<w:p …>…</w:p>` span, and inside each, the **`w:t` segments**
   (`/<w:t[^>]*>([^<]*)<\/w:t>/`) with their raw byte spans in the decoded
   string. `w:tab`, `w:br` and `w:cr` inside a run contribute to the
   PROJECTION (tab, space, space — mirroring `wordRuns` in `office.ts`) but
   never to the matchable text of a `w:t` segment.
3. The **projection** — the same view the model sees — is each paragraph's
   `w:t` text concatenated, XML-unescaped (`&amp;` → `&`, `&lt;` → `<`,
   `&gt;` → `>`, `&quot;` → `"`, `&apos;` → `'`), one paragraph per line. This
   is deliberately NOT `readDocx`'s markdown form: that form wraps runs in
   `**` and `*`, which would corrupt a find string the model quotes from the
   document.
4. A proposed edit is `{ find, replace }`. Matching runs against the projection
   paragraph by paragraph; a find must occur in EXACTLY ONE paragraph, and
   within that paragraph the match must span `w:t` segments contiguously (the
   projection between segments is empty inside a run, and a match crossing a
   paragraph boundary cannot happen by rule 3). First occurrence in that
   paragraph, and the paragraph must contain exactly one occurrence — an
   ambiguous or absent find is a validation fault, never a guess. A
   `w:tab`/`w:br`/`w:cr` inside a run contributes to the PROJECTION (tab,
   space, space — mirroring `wordRuns` in `office.ts`) as a GAP character: it
   sits between segments, and a find that crosses one is refused with its own
   fault, because the rewrite only splices `w:t` spans.
5. The rewrite replaces the matched raw span: the FIRST affected run's `w:t`
   keeps its formatting (its `rPr`, byte-identical) and receives the escaped
   replacement; every middle `w:t` of a multi-segment match is emptied.
   `xml:space="preserve"` is added to a `w:t` when the new text starts or ends
   with a space. Outside the matched spans, `word/document.xml` is
   byte-identical, and every other zip part is byte-identical because the copy
   is written with `writeZip` from the untouched bytes.
6. Newlines in `replace` are refused at validation (a paragraph boundary is not
   an edit the schema expresses; adding paragraphs is a different feature).
   Deleting text is `replace: ""` — the paragraph shell remains, which is the
   documented, honest behavior.

## The ops schema

The model answers with ONE JSON object, validated before anything is written:

```json
{ "kind": "edits", "ops": [ { "find": "shared drive", "replace": "Q3 archive" } ], "summary": "…" }
```

or, when the edit is not expressible:

```json
{ "kind": "unsupported", "reason": "the edit would add a table" }
```

Limits: 0..8 ops; each find 1..600 characters; each op must match exactly once
(in one paragraph) against the projection AS LEFT BY THE EARLIER OPS — the ops
compose, and all of them are validated before the single write. The write is
temp file + rename, so a crash mid-run cannot leave a half-written copy. Zero
ops is a valid answer for a document that already satisfies the task: the run
settles done, nothing is written, and no copy is created.

## The model view and the prompt

The model receives the projection, capped at about 12000 characters with a
visible `…(+N characters not shown)` marker when it cuts (the same honesty
rule as the observe cap). The proposal prompt states the schema, the
one-paragraph-one-match rule, the newline refusal, and the unsupported escape
hatch, and is sidecar-local like `AGENT_PROPOSE_PROMPT` (not in
`INSTRUCTION_BLOCKS`). One re-ask on an invalid proposal, carrying the exact
validation fault; a second invalid answer settles the run as failed. An
`unsupported` verdict settles as unresolved with the reason.

## The copy

- Name: `<base> (edited).docx` beside the source; ` (edited 2)`,
  ` (edited 3)`… on collision, never overwriting.
- `.docm` sources get a `.docm` copy (same bytes elsewhere, so the macros ride
  along untouched).
- The original's mtime and bytes are never touched; the run re-hashes the
  source after the run and verifies the hash is unchanged.

## Verification (before `done`)

A settled verdict of `done` REQUIRES all of these, checked against the copy
REOPENED FROM DISK:

1. Every part except `word/document.xml` is byte-equal to the source's part.
2. `word/document.xml` equals the engine's computed edited string (nothing
   else moved).
3. The copy's projection equals the source's projection with the ops applied
   textually — applying to text, not re-matching, so a find string inside a
   replacement cannot confuse the check.
4. The paragraph count is unchanged.
5. The source's sha256 is unchanged after the run.

Any verification fault settles `unresolved`, naming the copy path, never
`done`, and never deleting the copy — the person decides what to keep.

## Verdicts and events

The run reuses the `agentRun` machine: `running/done/unresolved/failed/
cancelled`, phases `observe (read) / propose / act (apply) / verify /
settled`, so the existing strip UI, `onAgentRun` wiring, and Stop path work
unchanged. Verdict lines speak plainly: `Done: the edited copy is saved as …`,
`Not done: the verification failed; the copy is at … for you to check or
delete`, `Unsupported: …`.

## The unsaved Document1 case

The dialog lists saved files only — an unsaved `Document1` has no file to
copy, and pretending otherwise would be a lie. If the person instead asks in a
Word WINDOW (the run's observe carries the window process), the refusal steer
gains one line: to save the file first, or use Edit a copy with the saved
file. The feature never drives the window.

## What is deliberately not here

- Writing into a live Word window (the standing decision from the Word pass).
- Adding or removing paragraphs, tables, or images; formatting changes
  (bold/italic/size); page layout. The ops schema edits TEXT only, in place.
- Multi-paragraph matches. Excel, PowerPoint, ODF, RTF, and legacy `.doc`
  (the legacy note applies, unchanged).

## Success criteria

On this PC, from the installed ARM64 build, with the local NPU model: an exact
replace lands in the copy with the source untouched (hash-equal), formatting
outside the edited range preserved byte for byte (parts other than
document.xml byte-equal), Stop cancels cleanly with no copy, an ambiguous find
is refused with a clear message, an unsupported edit reports its reason, and
the Notepad acceptance of v3 still passes on the same host.
